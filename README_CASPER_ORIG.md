# Casper Engineering Take-Home

## Objective

Build a **small full-stack product** around something you are genuinely passionate about.

It should create an experience that you personally find useful, interesting, or exciting.

This could be anything you genuinely care about: gaming, trading cards, sports, music, cars, cooking, fitness, collecting, travel, investing, or a niche hobby/community.

Pick something that feels unmistakably **you**, not something you think we want to see.

The end experience should make that passion overtly obvious. As an end user, we should quickly understand what you care about and why this product is exciting or useful to someone who shares that interest.

## What We Expect to See

Your submission should demonstrate:

- A coherent end-to-end product experience
- Authentication
- Multiple meaningful interactions throughout the product
- Interactions that go beyond a single happy path or one-button demo
- Non-trivial application logic
- A product we can open, use, and explore
- Clear prioritization within the timebox
- Enough working implementation for you to discuss and extend during the follow-up interview

We are intentionally not defining what the product should do, what data it should use, what technologies it should include beyond the language constraint, or what a good implementation looks like.

A useful framing question is:

**Who is this for, and what should they be able to do that feels valuable or delightful?**

## Constraints

### Time

You have **2 hours**.

You are **not expected to finish** the application.

Stop working when the two-hour timebox is complete and submit the project in whatever state it is in.

### Language

Use either:

- **Rust**
- **TypeScript**

Choose one.

## Everything Else Is Up to You

## Deployment

We expect you to submit a **deployed, accessible version of the product** in addition to the source code.

The product does not need to be complete or production-ready. We care that we can open it, use what you built, and experience the direction you chose within the two-hour timebox.

## Submission

Please submit:

- The source code
- A link to the deployed product
- The information necessary for us to run or inspect the project locally

If the application is incomplete, submit it as-is.

Include a brief note describing:

- What currently works
- What is incomplete
- How to run the project

## AI Tools

You may use AI-assisted development tools during the exercise.

You are responsible for the code you submit and should be prepared to discuss and work with it during the follow-up interview.
